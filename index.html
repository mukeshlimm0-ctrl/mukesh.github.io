01Foundations · Full stack development

Full stack is the whole journey, not one language.

A full-stack web application brings together the parts a person uses in a browser and the services that work behind it. The front end presents the interface; the back end handles application logic; a database stores information; and APIs let those parts communicate.

A full-stack developer can work across that path and understand how the pieces fit together. It does not mean knowing every tool or being an expert in every layer.

  • Front end: HTML, CSS, and JavaScript render the interface and respond to user actions.
  • Back end + API: server code validates requests, applies rules, and sends a response.
  • Data layer: a database stores and retrieves information the application needs.
Key idea: follow a request from the browser to the server and back—that connection is the “full stack.”

02Structure · HTML

HTML gives a page its meaning.

HTML (HyperText Markup Language) describes the structure and purpose of content. Semantic elements such as <main>, <nav>, <article>, and headings make a document easier for browsers, assistive technology, search tools, and other developers to understand.

Good HTML is more than a collection of tags. Headings should have a sensible order, links should describe their destination, and every form control needs a label. Native input types and attributes can provide useful browser validation before JavaScript is involved.

  • Use semantic elements to communicate what each region or item represents.
  • Connect a <label> to its input so it is easier to identify and operate.
  • Use built-in attributes such as required, minlength, and type="date".

03Presentation · CSS

CSS turns structure into experience.

CSS (Cascading Style Sheets) controls how HTML is presented. The cascade resolves which rules apply; specificity and source order help decide between competing declarations. Inheritance lets some properties, such as text color, flow from a parent to its children.

The box model describes an element as content surrounded by padding, border, and margin. Flexbox and Grid arrange elements; media queries adapt the layout to different screens. Custom properties keep repeated values consistent.

  • Separate content from presentation so each can be changed more easily.
  • Use responsive layouts and flexible measurements instead of designing for one screen size.
  • Keep motion subtle and respect the user’s reduced-motion preference.

04Framework · Bootstrap

Bootstrap speeds up consistent layouts.

Bootstrap is a front-end framework with a responsive, mobile-first grid plus ready-made components and utility classes. Its 12-column grid uses breakpoints: a column can take the full row on a small screen, then share space at larger widths.

Classes such as container, row, col-sm-6, and card provide a familiar starting point. Bootstrap does not replace HTML knowledge or thoughtful design: developers still choose semantic elements, check accessibility, and customize styles to suit the project.

  • Grid: responsive rows and columns arrange content across screen sizes.
  • Components: reusable patterns such as cards and buttons reduce repeated setup.
  • Utilities: concise classes adjust spacing, color, display, and more.

05Interaction · JavaScript

JavaScript makes the page respond.

JavaScript is a programming language that can run in the browser. It can listen for events, read or validate input, change the Document Object Model (DOM), and update interface state without reloading the page.

In a larger application, the browser may also call a back-end API. The small example here stays in the browser: it adds tasks to the DOM and lets you mark them complete. It does not save them to a database, so a refresh starts the list over.

  • Events: a submit or click tells the program when to act.
  • State: the completed-task count changes as the list changes.
  • Safer rendering: new task text is inserted with textContent, not treated as HTML.
Try it: add a task, then activate its circle to toggle completion. The count updates immediately.

  const title = input.value.trim();
  if (!title) return;

  const label = document.createElement("span");
  label.textContent = title;

Why use textContent? It treats user input as text rather than executable markup, which is a safer default for displaying it.
